### ANSWER
Prevent SQL injection by **never building SQL with user input via string concatenation or f-strings**. Instead, use **parameterized queries / prepared statements**, where the database driver sends the SQL structure and the data separately.

## Core rule

Unsafe:

```python
name = request.args.get("name")

# BAD: SQL injection risk
sql = f"SELECT * FROM users WHERE name = '{name}'"
cursor.execute(sql)
```

Safe:

```python
name = request.args.get("name")

# GOOD: parameterized query
cursor.execute("SELECT * FROM users WHERE name = %s", (name,))
```

The exact placeholder style depends on the database driver.

# 1. SQLite with `sqlite3`

SQLite uses `?` placeholders.

```python
import sqlite3

def get_user(user_id: int):
    conn = sqlite3.connect("app.db")
    cur = conn.cursor()

    cur.execute(
        "SELECT id, username, email FROM users WHERE id = ?",
        (user_id,)
    )

    user = cur.fetchone()
    conn.close()
    return user
```

Multiple parameters:

```python
cur.execute(
    """
    SELECT id, username, email
    FROM users
    WHERE username = ?
      AND email = ?
    ORDER BY id
    LIMIT ?
    """,
    (username, email, limit)
)
```

Insert:

```python
cur.execute(
    "INSERT INTO users (username, email) VALUES (?, ?)",
    (username, email)
)
```

Update:

```python
cur.execute(
    "UPDATE users SET email = ? WHERE id = ?",
    (new_email, user_id)
)
```

Delete:

```python
cur.execute(
    "DELETE FROM users WHERE id = ?",
    (user_id,)
)
```

PostgreSQL drivers commonly use `%s` placeholders.

# 4. SQLAlchemy Core

SQLAlchemy Core uses named parameters with `text()`.

```python
from sqlalchemy import create_engine, text

engine = create_engine("postgresql://myuser:mypassword@localhost/mydb")

def get_user(user_id: int):
    with engine.connect() as conn:
        result = conn.execute(
            text("SELECT id, username, email FROM users WHERE id = :user_id"),
            {"user_id": user_id}
        )
        return result.fetchone()
```

Multiple parameters:

```python
result = conn.execute(
    text("""
        SELECT id, username, email
        FROM users
        WHERE username = :username
          AND email = :email
        ORDER BY id
        LIMIT :limit
    """),
    {
        "username": username,
        "email": email,
        "limit": limit
    }
)
```

Insert:

```python
conn.execute(
    text("INSERT INTO users (username, email) VALUES (:username, :email)"),
    {"username": username, "email": email}
)
conn.commit()
```

Update:

```python
conn.execute(
    text("UPDATE users SET email = :email WHERE id = :user_id"),
    {"email": new_email, "user_id": user_id}
)
conn.commit()
```

Delete:

```python
conn.execute(
    text("DELETE FROM users WHERE id = :user_id"),
    {"user_id": user_id}
)
conn.commit()
```

# 5. SQLAlchemy ORM

The ORM is usually the safest option because it builds parameterized queries for you.

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from sqlalchemy.orm import declarative_base
from sqlalchemy import Column, Integer, String

Base = declarative_base()

class User(Base):
    __tablename__ = "users"

    id = Column(Integer, primary_key=True)
    username = Column(String)
    email = Column(String)

engine = create_engine("postgresql://myuser:mypassword@localhost/mydb")
Session = sessionmaker(bind=engine)

def get_user(user_id: int):
    session = Session()
    user = session.query(User).filter(User.id == user_id).first()
    session.close()
    return user
```

Multiple filters:

```python
users = session.query(User).filter(
    User.username == username,
    User.email == email
).limit(limit).all()
```

Insert:

```python
session = Session()
new_user = User(username=username, email=email)
session.add(new_user)
session.commit()
session.close()
```

Update:

```python
session = Session()
user = session.query(User).filter(User.id == user_id).first()
user.email = new_email
session.commit()
session.close()
```

Delete:

```python
session = Session()
user = session.query(User).filter(User.id == user_id).first()
session.delete(user)
session.commit()
session.close()
```

# 6. Django ORM

Django’s ORM also uses parameterized queries internally.

```python
from django.contrib.auth.models import User

def get_user(user_id: int):
    return User.objects.filter(id=user_id).first()
```

Multiple filters:

```python
users = User.objects.filter(
    username=username,
    email=email
)[:limit]
```

Insert:

```python
user = User.objects.create(username=username, email=email)
```

Update:

```python
User.objects.filter(id=user_id).update(email=new_email)
```

Delete:

```python
User.objects.filter(id=user_id).delete()
```

Avoid raw SQL unless necessary. If you must use it, use Django’s parameterized raw SQL:

```python
User.objects.raw(
    "SELECT * FROM auth_user WHERE id = %s",
    [user_id]
)
```

# 7. Flask example with SQLAlchemy

```python
from flask import Flask, request, jsonify
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from sqlalchemy.orm import declarative_base
from sqlalchemy import Column, Integer, String

app = Flask(__name__)

Base = declarative_base()

class User(Base):
    __tablename__ = "users"

    id = Column(Integer, primary_key=True)
    username = Column(String)
    email = Column(String)

engine = create_engine("sqlite:///app.db")
Session = sessionmaker(bind=engine)

@app.route("/users/<int:user_id>")
def get_user(user_id: int):
    session = Session()
    user = session.query(User).filter(User.id == user_id).first()
    session.close()

    if not user:
        return jsonify({"error": "User not found"}), 404

    return jsonify({
        "id": user.id,
        "username": user.username,
        "email": user.email
    })

@app.route("/users", methods=["POST"])
def create_user():
    data = request.get_json()

    username = data.get("username")
    email = data.get("email")

    if not username or not email:
        return jsonify({"error": "username and email are required"}), 400

    session = Session()
    user = User(username=username, email=email)
    session.add(user)
    session.commit()
    session.close()

    return jsonify({"id": user.id}), 201
```

# 8. Dynamic table or column names

Parameterized queries protect **values**, not SQL identifiers like table names, column names, or sort fields.

Unsafe:

```python
table = request.args.get("table")
sql = f"SELECT * FROM {table}"
cursor.execute(sql)
```

This is still vulnerable.

Safe approach: use an allowlist.

```python
ALLOWED_TABLES = {"users", "orders", "products"}

table = request.args.get("table")

if table not in ALLOWED_TABLES:
    raise ValueError("Invalid table name")

cursor.execute(f"SELECT * FROM {table}")
```

For sorting, also use an allowlist:

```python
ALLOWED_SORT_COLUMNS = {"id", "username", "email", "created_at"}

sort_column = request.args.get("sort", "id")
sort_direction = request.args.get("direction", "asc")

if sort_column not in ALLOWED_SORT_COLUMNS:
    raise ValueError("Invalid sort column")

if sort_direction.lower() not in {"asc", "desc"}:
    raise ValueError("Invalid sort direction")

cursor.execute(
    f"SELECT id, username, email FROM users ORDER BY {sort_column} {sort_direction}"
)
```

Better: use an ORM or query builder that supports safe dynamic sorting.

# 9. `LIMIT` and `OFFSET`

Use placeholders when possible.

SQLite:

```python
cursor.execute(
    "SELECT * FROM users ORDER BY id LIMIT ? OFFSET ?",
    (limit, offset)
)
```

PostgreSQL / MySQL:

```python
cursor.execute(
    "SELECT * FROM users ORDER BY id LIMIT %s OFFSET %s",
    (limit, offset)
)
```

If your driver does not support placeholders for `LIMIT`/`OFFSET`, validate and cast to integers:

```python
limit = int(limit)
offset = int(offset)
```

# 10. Stored procedures

If using stored procedures, call them with parameters.

`psycopg2` example:

```python
cur.execute("CALL get_user(%s)", (user_id,))
```

Avoid building dynamic SQL inside stored procedures using string concatenation.

# 11. Additional best practices

1. **Use an ORM when possible.**
   - SQLAlchemy ORM
   - Django ORM
   - Peewee
   - Tortoise ORM

2. **Use parameterized queries for all user input.**
   - Query values
   - `WHERE` clauses
   - `INSERT` values
   - `UPDATE` values
   - `LIMIT`/`OFFSET` when supported

3. **Do not use f-strings, `%` formatting, or `.format()` for SQL values.**

   Bad:

   ```python
   sql = f"SELECT * FROM users WHERE id = {user_id}"
   ```

   Good:

   ```python
   cursor.execute("SELECT * FROM users WHERE id = ?", (user_id,))
   ```

4. **Validate dynamic identifiers.**
   - Table names
   - Column names
   - Sort fields
   - Schema names

5. **Use least privilege.**
   Your web app database user should only have the permissions it needs.

6. **Use HTTPS and validate input types.**
   SQL injection prevention is not just about escaping; it is about separating code from data.

7. **Use a modern database driver.**
   Older or custom SQL builders may be easier to misuse.

# Quick reference

| Database / Driver | Placeholder |
|---|---|
| SQLite `sqlite3` | `?` |
| PostgreSQL `psycopg2` | `%s` |
| MySQL `PyMySQL` | `%s` |
| SQLAlchemy Core | `:name` |
| Django ORM | Use ORM filters |
| SQLAlchemy ORM | Use ORM filters |

Example:

```python
# SQLite
cursor.execute("SELECT * FROM users WHERE id = ?", (user_id,))

# PostgreSQL
cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))

# MySQL
cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))

# SQLAlchemy Core
conn.execute(text("SELECT * FROM users WHERE id = :user_id"), {"user_id": user_id})
```

The safest pattern is:

```python
# Use ORM
user = session.query(User).filter(User.id == user_id).first()
```

or, if using raw SQL:

```python
cursor.execute(
    "SELECT id, username, email FROM users WHERE id = %s",
    (user_id,)
)
```
