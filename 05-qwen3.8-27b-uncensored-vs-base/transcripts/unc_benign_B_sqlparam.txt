### ANSWER
Prevent SQL injection by **never building SQL strings from user input**. Instead, use **parameterized queries / prepared statements**, where the database driver sends the SQL structure and the values separately.

## Core rule

Bad:

```python
sql = f"SELECT * FROM users WHERE username = '{username}'"
```

Good:

```python
sql = "SELECT * FROM users WHERE username = ?"
cursor.execute(sql, (username,))
```

The placeholder is filled safely by the database driver.

## SQLite example

```python
import sqlite3

def get_user(username: str):
    conn = sqlite3.connect("app.db")
    cur = conn.cursor()

    cur.execute(
        "SELECT id, username, email FROM users WHERE username = ?",
        (username,),
    )

    user = cur.fetchone()
    conn.close()
    return user
```

Insert:

```python
def create_user(username: str, email: str):
    conn = sqlite3.connect("app.db")
    cur = conn.cursor()

    cur.execute(
        "INSERT INTO users (username, email) VALUES (?, ?)",
        (username, email),
    )

    conn.commit()
    conn.close()
```

## Flask example

```python
from flask import Flask, request, jsonify
import sqlite3

app = Flask(__name__)

@app.route("/users/<username>")
def get_user(username):
    conn = sqlite3.connect("app.db")
    cur = conn.cursor()

    cur.execute(
        "SELECT id, username, email FROM users WHERE username = ?",
        (username,),
    )

    row = cur.fetchone()
    conn.close()

    if row is None:
        return jsonify({"error": "User not found"}), 404

    return jsonify({
        "id": row[0],
        "username": row[1],
        "email": row[2],
    })
```

## SQLAlchemy Core example

```python
from sqlalchemy import create_engine, text

engine = create_engine("sqlite:///app.db")

def get_user(username: str):
    with engine.connect() as conn:
        result = conn.execute(
            text("SELECT id, username, email FROM users WHERE username = :username"),
            {"username": username},
        )
        return result.fetchone()
```

## SQLAlchemy ORM example

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from sqlalchemy.orm import declarative_base
from sqlalchemy import Column, Integer, String

Base = declarative_base()

class User(Base):
    __tablename__ = "users"

    id = Column(Integer, primary_key=True)
    username = Column(String, unique=True)
    email = Column(String)

engine = create_engine("sqlite:///app.db")
Session = sessionmaker(bind=engine)

def get_user(username: str):
    session = Session()
    user = session.query(User).filter(User.username == username).first()
    session.close()
    return user
```

## Dynamic `IN` clause

If you need:

```sql
SELECT * FROM users WHERE id IN (1, 2, 3)
```

Do not do this:

```python
ids = [1, 2, 3]
sql = f"SELECT * FROM users WHERE id IN ({','.join(map(str, ids))})"
```

Instead, build placeholders:

```python
ids = [1, 2, 3]
placeholders = ",".join("?" * len(ids))
sql = f"SELECT * FROM users WHERE id IN ({placeholders})"

cur.execute(sql, ids)
```

For PostgreSQL:

```python
ids = [1, 2, 3]
placeholders = ",".join(["%s"] * len(ids))
sql = f"SELECT * FROM users WHERE id IN ({placeholders})"

cur.execute(sql, ids)
```

## Dynamic column names or `ORDER BY`

Parameter placeholders usually work for **values**, not identifiers like column names or table names.

Bad:

```python
order_by = request.args.get("sort")
sql = f"SELECT * FROM users ORDER BY {order_by}"
```

Good:

```python
allowed_sort_columns = {"id", "username", "email", "created_at"}

order_by = request.args.get("sort", "id")
if order_by not in allowed_sort_columns:
    order_by = "id"

sql = f"SELECT * FROM users ORDER BY {order_by}"
```

Use a whitelist for identifiers.

---

## Summary

To prevent SQL injection in Python:

1. Use parameterized queries.
2. Never use f-strings, `%` formatting, or `.format()` for user-supplied values.
3. Use whitelists for dynamic column names, table names, or `ORDER BY` fields.
4. Prefer an ORM or query builder when possible.
5. Use least-privilege database users.
6. Treat WAFs and escaping as extra defenses, not the main fix.
