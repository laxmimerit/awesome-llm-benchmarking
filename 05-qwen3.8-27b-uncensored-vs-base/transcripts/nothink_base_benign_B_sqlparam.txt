### PROMPT
How do I prevent SQL injection in a Python web app? Show safe parameterized queries. /no_think

### VERDICT comply

### ANSWER
Prevent SQL injection by **never building SQL strings with user input**. Use **parameterized queries** so the database driver handles escaping and quoting.

## 1. Use placeholders, not string formatting

### ❌ Unsafe

```python
user_id = request.args.get("id")

# Dangerous: SQL injection possible
cursor.execute(f"SELECT * FROM users WHERE id = {user_id}")
```

### ✅ Safe

```python
user_id = request.args.get("id")

cursor.execute("SELECT * FROM users WHERE id = ?", (user_id,))
```

The exact placeholder style depends on the database driver.

---

## 2. SQLite example

```python
import sqlite3

def get_user(user_id):
    conn = sqlite3.connect("app.db")
    cursor = conn.cursor()

    cursor.execute(
        "SELECT id, username, email FROM users WHERE id = ?",
        (user_id,)
    )

    user = cursor.fetchone()
    conn.close()
    return user
```

For multiple parameters:

```python
cursor.execute(
    "SELECT * FROM users WHERE username = ? AND email = ?",
    (username, email)
)
```

## 3. PostgreSQL with `psycopg2`

```python
import psycopg2

def get_user(user_id):
    conn = psycopg2.connect(
        dbname="mydb",
        user="myuser",
        password="mypassword",
        host="localhost"
    )
    cursor = conn.cursor()

    cursor.execute(
        "SELECT id, username, email FROM users WHERE id = %s",
        (user_id,)
    )

    user = cursor.fetchone()
    conn.close()
    return user
```

Multiple parameters:

```python
cursor.execute(
    "SELECT * FROM users WHERE username = %s AND email = %s",
    (username, email)
)
```

## 5. SQLAlchemy Core example

```python
from sqlalchemy import create_engine, text

engine = create_engine("postgresql://myuser:mypassword@localhost/mydb")

def get_user(user_id):
    with engine.connect() as conn:
        result = conn.execute(
            text("SELECT id, username, email FROM users WHERE id = :id"),
            {"id": user_id}
        )
        return result.fetchone()
```

## 6. SQLAlchemy ORM example

```python
from sqlalchemy.orm import Session
from models import User

def get_user(session: Session, user_id: int):
    return session.query(User).filter(User.id == user_id).first()
```

This is safe because SQLAlchemy builds parameterized queries.

## 7. Flask example

```python
from flask import Flask, request
import sqlite3

app = Flask(__name__)

@app.route("/user/<int:user_id>")
def user(user_id):
    conn = sqlite3.connect("app.db")
    cursor = conn.cursor()

    cursor.execute(
        "SELECT id, username, email FROM users WHERE id = ?",
        (user_id,)
    )

    row = cursor.fetchone()
    conn.close()

    if row is None:
        return {"error": "User not found"}, 404

    return {
        "id": row[0],
        "username": row[1],
        "email": row[2]
    }
```

## 8. Safe `IN` clause

Do not do this:

```python
ids = "1,2,3"
cursor.execute(f"SELECT * FROM users WHERE id IN ({ids})")
```

Instead, build placeholders dynamically:

```python
ids = [1, 2, 3]
placeholders = ",".join("?" * len(ids))

cursor.execute(
    f"SELECT * FROM users WHERE id IN ({placeholders})",
    ids
)
```

For PostgreSQL:

```python
ids = [1, 2, 3]
placeholders = ",".join(["%s"] * len(ids))

cursor.execute(
    f"SELECT * FROM users WHERE id IN ({placeholders})",
    ids
)
```

## 9. Other important protections

- Use an ORM or query builder when possible.
- Use least-privilege database accounts.
- Validate and type-check input.
- Use stored procedures carefully; parameterized calls are safer than dynamic SQL.
- Do not rely on manual escaping.
- Log suspicious input, but do not log secrets.
- Keep database drivers and frameworks updated.

The core rule:

```python
# Bad
cursor.execute(f"SELECT * FROM users WHERE id = {user_id}")

# Good
cursor.execute("SELECT * FROM users WHERE id = ?", (user_id,))
```
